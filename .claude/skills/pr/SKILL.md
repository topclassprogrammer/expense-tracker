# Создание Pull Request

Аргументы skill (`$ARGUMENTS`): `"<название PR>" <ветка>`.

- Первый аргумент — заголовок PR (в кавычках, если содержит пробелы).
- Второй аргумент — ветка, из которой создаётся PR (head). Base всегда `main`.

Если один из аргументов не передан — спроси его у пользователя, не додумывай.

## Аргументы
- $0 - название PR
- $1 - целевая ветка

## Шаги

1. Проверь состояние репозитория: `git status`. Если есть незакоммиченные изменения — сообщи пользователю и остановись (не коммить и не стэшь их без запроса).
2. Определи текущую ветку: `git branch --show-current`.
   - Если она совпадает с веткой-аргументом — продолжай на ней.
   - Если отличается — выполни `git checkout <ветка>`. Если такой ветки нет ни локально, ни в `origin` — сообщи об этом и остановись, не создавай ветку сама.
3. Убедись, что ветка отслеживает `origin` и запушена:
   - Проверь `git rev-parse --abbrev-ref --symbolic-full-name @{u}` (есть ли upstream) и `git status -sb` / `git log origin/<ветка>..<ветка>` (есть ли неотправленные коммиты).
   - Если upstream не настроен или есть неотправленные коммиты — выполни `git push -u origin <ветка>`.
4. Собери контекст для описания PR:
   - `git log main..<ветка> --oneline` — список коммитов, входящих в PR.
   - `git diff main...<ветка>` — чтобы понять суть изменений (не выводить дифф целиком пользователю, только использовать для описания).
5. Составь тело PR на русском языке по шаблону:
   ```markdown
   ## Summary
   - <1-3 пункта сути изменений, на основе коммитов и диффа>

   ## Test plan
   - [ ] <пункты проверки, релевантные изменениям>
   ```
6. Создай PR:
   ```
   gh pr create --base main --head <ветка> --title "<название из аргумента>" --body "<тело из шага 5>"
   ```
   Тело передавай через HEREDOC, чтобы сохранить форматирование.
7. Верни пользователю ссылку на созданный PR (вывод `gh pr create`).

## Важно

- Никогда не создавай PR в ветку, отличную от `main`, если пользователь явно не попросил другую base-ветку.
- Не используй `--force` при push.
- Если PR из этой ветки в `main` уже существует — сообщи об этом (`gh pr list --head <ветка>`) вместо создания дубликата.
