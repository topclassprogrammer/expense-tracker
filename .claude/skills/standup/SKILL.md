# Standup-отчёт

Собирает коммиты **текущего git-пользователя** за **вчерашний календарный день** по **всем веткам** репозитория и формирует краткий отчёт: суть того, что было сделано и зачем — без перечисления файлов и без списка коммитов.

## Шаги

1. Определи текущего пользователя git: `git config user.name` / `git config user.email`.
2. Определи границы "вчера" в локальном времени (сегодняшняя дата берётся из системного контекста, а не вычисляется через shell):
   - `since` = вчера 00:00:00
   - `until` = сегодня 00:00:00
3. Собери коммиты автора за этот диапазон по всем веткам:
   ```
   git log --all --since="<вчера> 00:00:00" --until="<сегодня> 00:00:00" \
     --author="<email или name>" \
     --date=format:'%H:%M' \
     --pretty=format:'%H|%ad|%s|%D'
   ```
   Если автор не находится по email, попробуй по `user.name`. Если оба варианта дают пусто — явно сообщи об этом пользователю, не выдумывай коммиты.
4. Для общей картины изучи изменения (`git show --stat --format='' <hash>` и при необходимости `git show <hash>` по 1-2 крупным коммитам), но эти детали — только для себя, в отчёт файлы и хэши не выносятся.
5. Составь отчёт на русском языке — **2-3 абзаца связного текста**, без списков коммитов и без путей к файлам: что в целом было сделано за день, в каком направлении (например, "документация backend-модуля транзакций", "рефакторинг X"), и зачем. При необходимости упомяни ветку(и), если это важно для контекста.
6. Выведи отчёт в чат целиком.
7. Сохрани его в файл `docs/standup/<YYYY-MM-DD>.md` (дата — вчерашняя), создав директорию `docs/standup/`, если её нет.

## Важно

- Если за вчера коммитов нет — сообщи об этом прямо, не придумывай отчёт.
- Не переписывай уже существующий файл отчёта за другую дату; для той же даты — перезаписывай (повторный запуск за тот же день должен обновлять отчёт).
- Отчёт должен быть содержательным по сути изменений (на основе реального diff/stat), а не дословным пересказом commit message, но кратким по форме — без перечислений.
